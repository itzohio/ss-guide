# Le détournement de COM

- **Vue d'ensemble :** le Component Object Model (COM) est une technologie centrale de Windows qui permet à des composants logiciels (des objets) d'interagir, quel que soit le langage dans lequel ils sont écrits. Beaucoup de fonctions Windows en dépendent, dont le shell (Explorer), Internet Explorer et un paquet d'applications. Windows utilise massivement le registre pour gérer COM : il y stocke chaque objet, son Class ID (CLSID) et, surtout, l'emplacement du serveur (souvent une DLL, parfois un EXE) qui implémente ses fonctions. Le détournement de COM est une technique d'évasion et de persistance : on manipule ces entrées de registre pour rediriger les appels destinés à un objet légitime vers du code malveillant.
- **Mécanisme de l'évasion et de la persistance :**
  - Identification de la cible : l'attaquant choisit un objet COM souvent instancié par des processus légitimes, de préférence ceux qui démarrent tout seuls (`explorer.exe`, services système, applications courantes).
  - Manipulation du registre : le cœur du détournement, c'est de modifier les clés liées au CLSID de la cible. La cible classique est la sous-clé `InprocServer32`, qui pointe normalement vers la DLL légitime du serveur COM. L'attaquant change la valeur `(Default)` de cette clé (ou des clés liées selon la méthode) pour pointer vers sa DLL.
  - Emplacements : ces clés sont souvent sous `HKEY_CLASSES_ROOT\CLSID\{Target_CLSID}\InprocServer32`, ou, plus intéressant pour l'évasion, sous la ruche utilisateur `HKEY_CURRENT_USER\Software\Classes\CLSID\{Target_CLSID}\InprocServer32`. Les entrées dans HKCU ne demandent pas les droits admin, ce qui les rend accessibles à un malware ou un cheat qui tourne en utilisateur.
  - Exécution du code : quand une application légitime appelle l'objet COM détourné, le runtime COM lit l'entrée modifiée et charge la DLL de l'attaquant dans l'espace mémoire de l'application appelante, à la place de la DLL légitime.
  - Évasion : comme le code malveillant est chargé et exécuté par un processus légitime et de confiance dans le cadre normal de son fonctionnement, ça passe à travers les solutions de liste blanche qui bloquent les exe inconnus. L'activité paraît aussi moins suspecte dans les logs d'exécution qu'un cheat lancé tout seul.
  - Persistance : si l'objet détourné est chargé automatiquement au démarrage ou à la connexion (par `explorer.exe` ou un autre processus d'auto-start), le code malveillant (un loader ou le cheat lui-même) s'exécute à chaque démarrage ou connexion, sans avoir besoin d'une clé Run ni d'une tâche planifiée.
