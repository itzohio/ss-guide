# Dépannage et détection d'évasion

Un joueur peut essayer de désactiver, vider ou bricoler Prefetch pour effacer ses traces. Il faut connaître ces techniques :

- **Prefetch désactivé (registre) :** le réglage principal est la valeur DWORD `EnablePrefetcher` dans `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management\PrefetchParameters`. Les valeurs courantes : `0` (désactivé), `1` (prefetch des programmes), `2` (prefetch du démarrage), `3` (les deux, par défaut). Trouver `0` pendant un check est suspect : c'est une désactivation volontaire.
- **Service SysMain arrêté :** c'est le service `sysmain` (ancien Superfetch) qui gère Prefetch. Vérification : `sc query sysmain` dans un CMD admin. Si le `STATE` n'est pas `RUNNING`, Prefetch ne tourne pas. Redémarrer le service peut être nécessaire pour que les logs reprennent, mais ça vide aussi certains caches volatils, ce qui peut gêner l'analyse. Le trouver arrêté sans raison valable, c'est un signal.
- **Permissions modifiées (bypass CACLS/ICACLS) :** un tricheur peut changer les ACL du dossier `C:\Windows\Prefetch` pour empêcher le système ou SysMain d'écrire des `.pf` ou d'en mettre à jour. Ça se fait avec `cacls` ou `icacls`. On vérifie dans l'onglet Sécurité des propriétés du dossier. Les changements récents de permissions (autoriser ou refuser l'écriture) se trouvent souvent dans le journal USN (`$UsnJrnl`), via les codes `SECURITY_CHANGE` liés au chemin du dossier Prefetch.
- **Fichiers Prefetch cachés :** un `.pf` peut porter l'attribut Caché. Un `dir /ah C:\Windows\Prefetch` en admin les révèle.
- **Prefetch vidé :** le joueur peut simplement supprimer le contenu de `C:\Windows\Prefetch`. Un dossier vide, ou sans entrées attendues (`explorer.exe`, `AnyDesk.exe`, le jeu) alors que SysMain tourne et que Prefetch est activé dans le registre, c'est très parlant. Le journal USN (`$UsnJrnl`) est l'outil principal pour le prouver : il logge plein de `FILE_DELETE` correspondant à des `.pf` au moment du nettoyage.
